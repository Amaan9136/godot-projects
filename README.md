## 1. The big picture

A Godot game is a **tree of nodes**. Nodes are grouped into **scenes**. Scenes can be nested inside other scenes. Scripts attach to nodes to give them behavior.

```text
Engine
 └── SceneTree  (the running game)
      └── Root Window
           └── Your main scene
                ├── Node A  (+ optional script)
                ├── Node B
                │    └── Child of B
                └── Node C
```

Three ideas carry most of Godot:

| Idea | Meaning |
|---|---|
| **Node** | The smallest building block. Each node type does one job (draw a sprite, detect collisions, play a sound, show text). |
| **Scene** | A saved tree of nodes. A scene can be a player, an enemy, a menu, a level, or a whole game. |
| **Signal** | An event a node emits so other nodes can react without being tightly coupled. |

Everything else (physics, UI, audio, animation) is built from these.

## 2. `.gd` vs `.tscn`: logic vs structure/design

A useful starting analogy:

```text
.gd   → works like JavaScript   (behavior, logic, "what happens")
.tscn → works like HTML + CSS   (structure and appearance, "what exists and how it looks")
```

More precisely, `.tscn` is closest to **HTML + inline styles**. It lists *which nodes exist* (the HTML part) and *what their property values are* (the style part). Godot's actual CSS equivalent is a **Theme** resource (`.tres`), which is covered in the [UI section](#13-ui-control-nodes-and-canvaslayer).

The two files cooperate. The `.tscn` creates and configures things. The `.gd` makes them do things.

### Side-by-side example: a clickable button with a counter

**The web way**

```html
<!-- index.html: structure -->
<button id="btn">Clicked: 0</button>
```

```css
/* style.css: design */
#btn {
  position: absolute;
  top: 20px;
  right: 20px;
  font-size: 40px;
  color: white;
  background: #3b82f6;
}
```

```js
// app.js: logic
let count = 0;
const btn = document.getElementById("btn");

btn.addEventListener("click", () => {
  count += 1;
  btn.textContent = `Clicked: ${count}`;
});
```

**The Godot way**

```ini
; counter.tscn: structure + design (auto-generated by the editor)
[gd_scene format=3]

[ext_resource type="Script" path="res://counter.gd" id="1"]

[node name="Counter" type="Control"]
script = ExtResource("1")

[node name="Btn" type="Button" parent="."]
offset_left = 520.0
offset_top = 20.0
offset_right = 700.0
offset_bottom = 80.0
theme_override_font_sizes/font_size = 40
text = "Clicked: 0"
```

```gdscript
# counter.gd: logic
extends Control

var count: int = 0

@onready var btn: Button = $Btn


func _ready() -> void:
    btn.pressed.connect(_on_btn_pressed)


func _on_btn_pressed() -> void:
    count += 1
    btn.text = "Clicked: %d" % count
```

### Mapping the pieces

| Web | Godot |
|---|---|
| `<button id="btn">` | `[node name="Btn" type="Button"]` in `.tscn` |
| Nesting of HTML tags | `parent="."` / `parent="Some/Path"` in `.tscn` |
| CSS properties (`font-size`, `color`) | Property lines in `.tscn` (`theme_override_font_sizes/font_size = 40`) |
| `document.getElementById("btn")` | `$Btn` or `get_node("Btn")` |
| `addEventListener("click", fn)` | `btn.pressed.connect(fn)` |
| `<script src="app.js">` | `script = ExtResource(...)` on a node |

### Rules of thumb

- **Appearance, position, which nodes exist, default values** → set in the editor (stored in `.tscn`).
- **Anything that changes while the game runs, reacts to input, or makes decisions** → `.gd`.
- **Values you want to tweak in the Inspector without editing code** → `@export var` in `.gd`.
- You *can* hand-edit `.tscn` files (they are plain text), but let the editor write them. A manual typo can break the scene.
- You *can* build everything in code (`Button.new()` then `add_child(...)`), but the editor is better for static layout.

| Web concept | Godot equivalent |
|---|---|
| DOM tree | Scene tree |
| HTML element | Node |
| React component | Scene (reusable, instanced) |
| Component props | `@export` variables |

| Viewport meta / media queries | Stretch mode + aspect + anchors |
| Browser devtools console | Output panel + Debugger |

## 4. Project structure

Godot does not force a folder layout. Pick one and stay consistent. Two common patterns:

**Group by type** (good for tiny projects)

```text
project/
├── project.godot
├── scenes/
├── scripts/
└── assets/
```

**Group by feature** (good as projects grow; scene and script sit together)

```text
project/
├── project.godot
├── player/
│   ├── player.tscn
│   └── player.gd
├── enemy/
│   ├── enemy.tscn
│   └── enemy.gd
├── ui/
│   ├── hud.tscn
│   └── hud.gd
├── scripts/
│   └── systems/        ← autoloads and global logic
├── assets/
│   ├── sprites/
│   ├── audio/
│   └── fonts/
└── main.tscn
```

Guidelines:

- Only create a folder when you have something to put in it.
- `snake_case` for file and folder names. `PascalCase` for node names and `class_name`.
- Paths in Godot start with `res://` (project root). Never use absolute OS paths.
- Always move or rename files **inside the Godot FileSystem dock**, not in Explorer. Godot then updates references automatically.

### Files you will see

| File | Purpose | Commit it? |
|---|---|---|
| `project.godot` | Project settings (like `package.json` + config) | Yes |
| `*.tscn` | Scene (text) | Yes |
| `*.gd` | Script | Yes |
| `*.gd.uid` | Stable ID for a script (Godot 4.4+) | Yes |
| `*.tres` | Saved Resource (text) | Yes |
| `*.import` | Import settings for an asset | Yes |
| `.godot/` | Editor cache and imported data | **No** |
| `export_presets.cfg` | Export settings (may contain paths) | Usually yes; keep secrets out |
| `*.keystore`, `*.jks` | Android signing keys | **Never** |

## 5. Scenes and nodes

### Common 2D node types

| Node | Use it for |
|---|---|
| `Node` | Pure logic with no position (managers, listeners) |
| `Node2D` | Anything with a 2D position, rotation, scale |
| `Sprite2D` | Drawing an image |
| `AnimatedSprite2D` | Frame-by-frame animation |
| `CharacterBody2D` | Something you move with code and that collides (player) |
| `RigidBody2D` | Something driven by the physics engine (crates, balls) |
| `StaticBody2D` | Solid, immovable things (walls, floors) |
| `Area2D` | Detects overlaps; does not block movement (pickups, hitboxes, triggers) |
| `CollisionShape2D` | Defines the physical shape for a body or area (needs a parent that is a body/area) |
| `Camera2D` | Controls what part of the world is visible |
| `Timer` | Fires `timeout` after a delay |
| `AudioStreamPlayer` | Plays sound (non-positional) |
| `GPUParticles2D` / `CPUParticles2D` | Particle effects |
| `CanvasLayer` | A separate drawing layer (UI, overlays) |
| `Label`, `Button`, `TextureRect`, `ColorRect` | UI building blocks |
| `VBoxContainer`, `HBoxContainer`, `MarginContainer` | UI layout (like flexbox) |

### Transform basics (2D)

- `position`: local position relative to the parent.
- `global_position`: position in world space.
- `rotation`: radians (use `deg_to_rad()` for degrees).
- `scale`: `Vector2`.
- **Y increases downward** in 2D. The top-left of the screen is `(0, 0)`.

### Instancing scenes

Instancing is how you reuse a scene: like rendering a React component many times.

```gdscript
@export var enemy_scene: PackedScene   # assign in the Inspector

func spawn() -> void:
    var enemy := enemy_scene.instantiate()
    enemy.position = Vector2(100, 0)
    add_child(enemy)                    # nothing appears until it's in the tree
```

Alternative: `preload("res://enemy/enemy.tscn")` loads at compile time. Prefer `@export` when you want to swap the scene without editing code.

### Removing nodes

```gdscript
queue_free()   # safe: deletes at the end of the current frame
```

Avoid `free()` unless you know exactly why you need it.

## 6. GDScript essentials

### Python vs GDScript

| Python | GDScript |
|---|---|
| `def move(speed):` | `func move(speed):` |
| `def move(speed: float) -> None:` | `func move(speed: float) -> void:` |
| `x = 5` | `var x = 5` (or typed: `var x: int = 5`) |
| `x := 5` does not exist | `var x := 5` infers the type |
| `class Foo(Bar):` | file starts with `extends Bar` |
| `self.x` | `self.x` or just `x` |
| `None` | `null` |
| `True / False` | `true / false` |
| `and / or / not` | `and / or / not` (also `&& || !`) |
| `elif` | `elif` |
| `for i in range(5):` | `for i in range(5):` |
| `"%d" % n` | `"%d" % n` |
| `f"{n}"` | `str(n)` or `"%s" % n` (no f-strings) |
| `import module` | `preload("res://file.gd")` / `class_name` |
| `pass` | `pass` |
| `# comment` | `# comment` |
| Indentation | Indentation (tabs by default in Godot) |

### Variable keywords

```gdscript
extends CharacterBody2D                 # what this script's node is

class_name Player                       # optional: global type name

signal died                             # declares an event

const MAX_HP: int = 100                 # constant

@export var speed: float = 400.0        # editable in the Inspector
@export var enemy_scene: PackedScene

var health: int = MAX_HP                # normal variable

@onready var label: Label = $Label      # assigned when node is ready
```

### `@onready` and `$`

`$Label` is shorthand for `get_node("Label")`. Child nodes only exist after the node enters the tree, so a plain `var x = $Label` at the top of a script fails. `@onready` delays the assignment until `_ready()` time.

```gdscript
@onready var score_label: Label = $HUD/ScoreLabel     # path is relative to this node
```

### Lifecycle functions

| Function | When it runs |
|---|---|
| `_init()` | Object created (children not available yet) |
| `_enter_tree()` | Node added to the tree |
| `_ready()` | Node and all children are ready (runs once; children first) |
| `_process(delta)` | Every rendered frame |
| `_physics_process(delta)` | Every physics tick (fixed rate, default 60/s) |
| `_input(event)` | For every input event, early |
| `_unhandled_input(event)` | For input that UI did not consume |
| `_exit_tree()` | Node removed from the tree |

### Useful built-ins

```gdscript
print("hello", x)                     # Output panel
push_warning("careful")               # yellow in Debugger
push_error("broken")                  # red in Debugger

randomize()                           # seed RNG (automatic in Godot 4)
randf()                               # float 0.0 - 1.0
randf_range(10.0, 20.0)               # float in range
randi_range(1, 6)                     # int in range

clamp(value, min, max)                # works on numbers
clampf(value, min, max)               # typed float version
maxf(a, b)   minf(a, b)               # typed float min/max
lerp(a, b, t)                         # blend between a and b

get_tree()                            # the SceneTree
get_viewport_rect().size              # screen size in game pixels
```

### Arrays and dictionaries

```gdscript
var items: Array[String] = ["a", "b"]
items.append("c")
for item in items:
    print(item)

var stats := {"hp": 10, "mana": 5}
stats["hp"] -= 1
for key in stats:
    print(key, stats[key])
```

### Enums and match

```gdscript
enum State { IDLE, RUNNING, DEAD }
var state: State = State.IDLE

match state:
    State.IDLE:
        pass
    State.RUNNING:
        pass
    State.DEAD:
        pass
```

## 7. The game loop and delta time

A game is a loop that repeats many times per second:

```text
read input → update state → draw → repeat
```

Godot runs that loop for you. You hook into it with `_process` and `_physics_process`.

### `delta`

`delta` is the number of seconds since the last frame. Always multiply movement by it so behavior does not depend on frame rate.

```gdscript
# WRONG: faster on a 144 Hz screen than a 30 Hz one
position.x += 5

# RIGHT: 300 pixels per second on any device
position.x += 300.0 * delta
```

### `_process` vs `_physics_process`

| | `_process(delta)` | `_physics_process(delta)` |
|---|---|---|
| Rate | Once per rendered frame (varies) | Fixed (default 60 per second) |
| Use for | Visuals, UI updates, timers you display | Movement of physics bodies, collisions, anything using `move_and_slide()` |
| Why | Matches what the player sees | Keeps physics stable and consistent |

### Vector2

A `Vector2` holds `x` and `y`. It represents positions, directions, and velocities.

```gdscript
var pos := Vector2(100, 200)
var dir := Vector2.LEFT                 # (-1, 0)
var move := dir * 300.0 * delta         # scaled by speed and time
var d := pos.distance_to(Vector2.ZERO)
var n := Vector2(3, 4).normalized()     # length 1, same direction
```

Constants: `Vector2.ZERO`, `UP`, `DOWN`, `LEFT`, `RIGHT`.

### Timers

Two options:

```gdscript
# 1) Timer node (configure Wait Time and Autostart in the Inspector)
@onready var timer: Timer = $Timer
func _ready() -> void:
    timer.timeout.connect(_on_timer_timeout)

# 2) One-off delay in code
await get_tree().create_timer(2.0).timeout
print("2 seconds later")
```

## 8. Signals (events)

A signal is Godot's event system. A node **emits** a signal and any number of other nodes can **connect** to it.

```js
// JS equivalent
emitter.on("scoreChanged", (score) => { label.textContent = score; });
emitter.emit("scoreChanged", 10);
```

```gdscript
# GDScript
signal score_changed(new_score: int)       # declare

score_changed.emit(10)                     # emit

other_node.score_changed.connect(_on_score_changed)   # connect

func _on_score_changed(new_score: int) -> void:
    label.text = "Score: %d" % new_score
```

### Two ways to connect

1. **In the editor:** select the node → **Node** tab → **Signals** → double-click a signal. Godot writes a `[connection ...]` line in the `.tscn`.
2. **In code:** `node.signal_name.connect(callable)`.

> **Pick one per signal.** Connecting the same signal in both places runs your handler twice.

### Why signals matter

They let a node announce what happened without knowing who is listening. The enemy says "I was hit". It does not need a reference to the score system, the UI, or the sound player. This keeps scenes independent and reusable.

### Built-in signals worth knowing

| Node | Signal | Fires when |
|---|---|---|
| `Button` | `pressed` | Clicked or tapped |
| `Timer` | `timeout` | Wait time elapsed |
| `Area2D` | `body_entered(body)` | A physics body enters |
| `Area2D` | `area_entered(area)` | Another area enters |
| `AnimationPlayer` | `animation_finished(name)` | Animation ends |
| `Node` | `tree_exited` | Node leaves the tree |

## 9. Groups

A group is a string tag you attach to nodes. Think of it as a CSS class used for lookups.

```gdscript
add_to_group("enemies")                          # in code
# or: Node dock → Groups tab in the editor

if body.is_in_group("player"):
    print("it's the player")

for e in get_tree().get_nodes_in_group("enemies"):
    e.queue_free()

get_tree().call_group("enemies", "freeze")       # call a method on all members
```

Use groups to identify types of nodes in collision callbacks and to find many nodes at once.

## 10. Autoloads (global singletons)

An autoload is a script (or scene) Godot loads automatically at startup and keeps alive for the whole run. It is accessible from anywhere by its name. This is the Godot version of a global store (Zustand/Redux).

**Register:** Project → Project Settings → **Globals** (or **Autoload**) → add the script → give it a name such as `GameManager`.

```gdscript
# game_manager.gd (autoload)
extends Node

signal score_changed(new_score: int)
var score: int = 0

func add_score(n: int = 1) -> void:
    score += n
    score_changed.emit(score)
```

```gdscript
# any other script
GameManager.add_score()
GameManager.score_changed.connect(_on_score_changed)
```

### Important gotchas

- **Autoloads survive scene changes and scene reloads.** Their variables do **not** reset when you call `reload_current_scene()` or `change_scene_to_file()`. Reset them yourself.
- Use autoloads for truly global things: game state, settings, audio manager, save/load. Do not make everything global.
- Autoloads sit in the tree beside your main scene, not inside it.

## 11. Input

### Input Map

Define named actions in **Project → Project Settings → Input Map**. Bind keys, gamepad buttons, or touch to each action. Code uses names, not keys, so you can rebind without code changes.

```gdscript
# Polling (check every frame)
var dir := Input.get_axis("move_left", "move_right")     # -1, 0, or 1
if Input.is_action_pressed("move_left"):   pass          # held down
if Input.is_action_just_pressed("jump"):   pass          # pressed this frame

# Event-based
func _unhandled_input(event: InputEvent) -> void:
    if event.is_action_pressed("restart"):
        restart()
```

### `_input` vs `_unhandled_input`

- `_input` sees every event first.
- `_unhandled_input` only sees events not already consumed by UI (a button click is consumed). Prefer it for gameplay keys.

### Touch input (mobile)

```gdscript
func _input(event: InputEvent) -> void:
    if event is InputEventScreenTouch:
        if event.pressed:
            print("touch down at ", event.position, " finger ", event.index)
        else:
            print("touch up")
    elif event is InputEventScreenDrag:
        print("dragging at ", event.position)
```

Options for mobile controls:

- `TouchScreenButton` node (maps a touch area to an Input Map action).
- Custom on-screen `Control` buttons.
- Direct drag/tap handling as above.

Enable **Project Settings → Input Devices → Pointing → Emulate Touch From Mouse** to test touch with a mouse on desktop.

## 12. Physics and collision

### Body types, picked by job

| Need | Use |
|---|---|
| You control it with code and it must collide | `CharacterBody2D` |
| Physics engine controls it | `RigidBody2D` |
| Immovable solid | `StaticBody2D` |
| Detect overlap but don't block | `Area2D` |

Every body or area needs a **`CollisionShape2D`** child with a shape assigned, or it has no physical presence.

### `CharacterBody2D` movement

```gdscript
extends CharacterBody2D

@export var speed: float = 400.0

func _physics_process(delta: float) -> void:
    var direction := Input.get_axis("move_left", "move_right")
    velocity.x = direction * speed
    move_and_slide()          # applies velocity and handles collisions
```

### Layers and masks

Each collision object has two settings:

- **Layer:** "What am I?" (which layers I exist on)
- **Mask:** "What do I look for?" (which layers I detect or collide with)

```text
Layer 1 = player
Layer 2 = enemies

Player:  layer = 1,  mask = (whatever it must collide with)
Enemy:   layer = 2,  mask = 1      → enemy detects the player
```

An object `A` detects `B` only if `B`'s **layer** is in `A`'s **mask**. Name your layers in **Project Settings → Layer Names → 2D Physics** to keep this readable.

### Detecting overlaps with `Area2D`

```gdscript
extends Area2D

func _ready() -> void:
    body_entered.connect(_on_body_entered)

func _on_body_entered(body: Node2D) -> void:
    if body.is_in_group("player"):
        print("player touched me")
```

- `body_entered` is for physics bodies (`CharacterBody2D`, `RigidBody2D`, `StaticBody2D`).
- `area_entered` is for other `Area2D` nodes.

## 13. UI (Control nodes and CanvasLayer)

*(Sections are numbered to match the table of contents; section 12 above covers physics.)*

### CanvasLayer

A `CanvasLayer` renders independently of the world and any `Camera2D`. Put HUD and menus inside one so they stay fixed on screen.

```text
Main
├── World stuff (Node2D, player, enemies)
└── HUD (CanvasLayer)
     ├── ScoreLabel
     └── PauseMenu
```

### Control nodes and layout

All UI nodes inherit from `Control`. Positioning uses **anchors** (relative to the parent) and **offsets** (pixels from the anchors).

- Use the toolbar **Layout** dropdown for presets: Top Left, Top Right, Center, **Full Rect**, etc.
- **Containers** (`VBoxContainer`, `HBoxContainer`, `GridContainer`, `MarginContainer`, `CenterContainer`) arrange their children automatically. Think flexbox:

| CSS | Godot |
|---|---|
| `display: flex; flex-direction: column;` | `VBoxContainer` |
| `display: flex; flex-direction: row;` | `HBoxContainer` |
| `display: grid;` | `GridContainer` |
| `padding` | `MarginContainer` + theme margin overrides |
| `justify-content: center` | Container **Alignment** = Center |
| `align-self: center` | Control **Container Sizing → Horizontal = Shrink Center** |
| `flex-grow: 1` | Container Sizing → **Expand** |
| `position: absolute` | Anchors/offsets on a plain `Control` |

### Styling: Theme vs overrides

The closest thing to CSS in Godot is a **Theme** resource (`.tres`): a reusable bundle of fonts, colors, and styleboxes applied to a node and all its children.

```text
Per-node override (like inline style):
Inspector → Theme Overrides → Font Sizes → Font Size = 40

Shared styling (like a stylesheet):
Create a Theme resource, set it on a root Control; all descendants inherit it.
```

Use overrides for one-offs. Use a Theme once you repeat the same styling in several places.

### Labels and text

```gdscript
label.text = "Score: %d" % score
label.add_theme_font_size_override("font_size", 40)     # set in code
```

## 14. Pausing and process modes

`get_tree().paused = true` freezes processing, physics, timers, and input for every node whose **Process Mode** respects pause.

| Process Mode | Behavior |
|---|---|
| `Inherit` (default) | Same as parent |
| `Pausable` | Stops when the tree is paused |
| `When Paused` | Runs only while paused |
| `Always` | Runs regardless |
| `Disabled` | Never runs |

Common pattern: pause the game on game over or a pause menu, but give the menu/UI `Always` so its buttons still respond.

```gdscript
func _ready() -> void:
    process_mode = Node.PROCESS_MODE_ALWAYS     # or set it in the Inspector → Process → Mode
```

> If a button does nothing after you pause the tree, its process mode is almost certainly the cause.

## 15. Resolution, stretch, and aspect ratios

Configured in **Project Settings → Display → Window**.

| Setting | Meaning |
|---|---|
| **Viewport Width / Height** | The "design resolution" your game logic uses (e.g. `720 x 1280`). |
| **Window Width / Height Override** | Size of the desktop window while testing (does not change game logic). |
| **Stretch Mode** | How the game scales to the real window. |
| **Stretch Aspect** | What to do when the real aspect ratio differs. |
| **Handheld → Orientation** | Portrait or landscape on mobile. |

### Recommended defaults for 2D games

```text
Stretch Mode:   canvas_items    (scales 2D and UI crisply)
Stretch Aspect: expand          (fills the screen; shows extra space instead of black bars)
```

- `keep` adds black bars to preserve the exact aspect ratio.
- `expand` keeps your design area and reveals more world on taller/wider screens. Use anchors on UI so it adapts.
- Anchor UI to edges and use containers. Do not position UI with fixed pixel coordinates from the top-left only.

### Portrait vs landscape

| | Portrait | Landscape |
|---|---|---|
| Natural for | One-handed, vertical dodgers/runners, puzzle | Platformers, racing, strategy |
| Thumb reach | Easy | Needs two hands |
| Pick based on | The game's primary motion axis and how it is held | |

Choose one per project and set it in Handheld → Orientation.

### Safe areas

Phones have notches and rounded corners. Query `DisplayServer.get_display_safe_area()` and keep important UI inside it.

## 16. Resources

A **Resource** is a data object that can be saved to disk and shared (`.tres` text or `.res` binary). Textures, fonts, audio streams, themes, and shapes are all Resources.

Custom data containers:

```gdscript
# enemy_stats.gd
class_name EnemyStats
extends Resource

@export var max_hp: int = 10
@export var speed: float = 200.0
```

```gdscript
# enemy.gd
@export var stats: EnemyStats
func _ready() -> void:
    print(stats.speed)
```

Create a `.tres` of `EnemyStats` in the editor (right-click in FileSystem → New Resource). Now you can tune enemies as data, like a JSON config, with Inspector editing.

> Resources are **shared by default** between nodes that reference the same file. Editing one at runtime changes it for all. Call `.duplicate()` if you need a private copy.

## 19. Debugging

### The tools

- **Output panel:** `print()` messages and errors.
- **Debugger panel → Errors:** stack traces with file and line numbers.
- **Debugger → Profiler / Monitors:** FPS, frame time, memory, object counts.
- **Remote tab in the Scene dock (while running):** inspect the live node tree and properties.
- **Debug → Visible Collision Shapes:** draws collision shapes while running.
- **Breakpoints:** click left of a line number in Godot's script editor (or VS Code with godot-tools).

### How to read an error

```text
E 0:00:03:123   enemy.gd:12 @ _physics_process(): Invalid access to property or key 'x' on a base object of type 'Nil'.
  <GDScript Source>enemy.gd:12 @ _physics_process()
```

1. **File and line:** `enemy.gd`, line 12.
2. **Message:** you accessed something on a `Nil` (null) object.
3. **Likely cause:** a node path was wrong, or the variable was never assigned.
4. **Check:** is the node name spelled exactly right? Is the `@onready` assigned? Was the `@export` filled in the Inspector?

### Debugging checklist

- Spelling and capitalization of node paths (`$HUD/ScoreLabel`).
- Script attached to the right node?
- `@export` references assigned in the Inspector?
- Signal connected twice (editor and code)?
- Collision layers and masks correct?
- Node process mode correct when paused?
- Autoload variables reset after a scene reload?

## 20. Exporting (Windows and Android)

### Build types

| Type | What it is | Use for |
|---|---|---|
| **Editor run** (F5) | Runs inside the editor | Daily development |
| **Debug export** | Standalone build with debug features and logging | Testing on device |
| **Release export** | Optimized, no debug features, signed for stores | Shipping |

### Windows

1. Project → **Export…** → **Add…** → **Windows Desktop**.
2. If prompted, install **export templates**: Editor → Manage Export Templates → Download and Install (the template version must match your Godot version exactly).
3. Choose a path and **Export Project**.

### Android: required pieces

You need:

- **Android SDK** (command-line tools, platform-tools, build-tools, platform)
- A **JDK** of the version your Godot release requires
- Godot's **Export Templates**
- A **debug keystore** (for testing) and a **release keystore** (for stores)

> Requirements change between Godot versions. Always confirm exact SDK, build-tools, and JDK versions in the official docs for your Godot release: https://docs.godotengine.org/en/stable/tutorials/export/exporting_for_android.html

Configure in **Editor → Editor Settings → Export → Android**:

- Android SDK Path
- Java SDK Path
- Debug Keystore (Godot can generate one)

### Phone setup

1. Settings → About phone → tap **Build number** 7 times to enable Developer Options.
2. Settings → Developer options → enable **USB debugging**.
3. Connect via USB and accept the RSA prompt on the phone.

### ADB commands

```powershell
adb devices                               # list connected devices
adb install -r path\to\game.apk           # install or replace
adb logcat -s godot                       # Godot logs only
adb logcat *:E                            # errors only
adb uninstall your.package.name           # remove the app
adb shell dumpsys gfxinfo your.package.name   # frame stats
```

If `adb` is not recognized, add `<Android SDK>\platform-tools` to your PATH.

### One-click deploy

With the phone connected, Godot shows a device icon in the top-right toolbar (Remote Debug / one-click deploy). It builds, installs, and launches on the device.

### Release signing (Play Store)

- Generate a **release keystore** once and back it up. Losing it can block updates.
- Use **AAB** (Android App Bundle) for Play Store; **APK** for direct install.
- **Never** commit keystores or passwords.

### iOS

Requires a Mac with Xcode and an Apple Developer account. Export from Godot to an Xcode project, then build and sign in Xcode.

## 21. Performance basics

| Term | Meaning |
|---|---|
| **FPS** | Frames per second. 60 is the usual target; 30 is acceptable for some mobile games. |
| **Frame time** | Milliseconds per frame. 60 FPS = 16.6 ms budget. |
| **CPU bound** | Slow because of script logic, physics, or too many nodes. |
| **GPU bound** | Slow because of drawing: big textures, overdraw, shaders, particles. |
| **Draw calls** | Number of separate draw commands per frame. Fewer is better. |
| **Memory** | Textures and audio dominate; large images cost RAM even if drawn small. |

### Habits that matter early

- **Measure first.** Use Debugger → Monitors/Profiler before optimizing.
- Remove nodes you are done with (`queue_free()`), especially anything spawned repeatedly. Leaked nodes are a classic slow-down.
- Avoid heavy work in `_process` (searching the tree, allocating every frame).
- Cache node references with `@onready` rather than calling `get_node()` every frame.
- Keep textures only as large as needed. Use texture atlases when sprites multiply.
- Use fewer, simpler collision shapes.
- Test on a real mid-range phone, not only on your PC.

Enable the FPS counter in debug builds with `Engine.get_frames_per_second()`:

```gdscript
fps_label.text = "FPS: %d" % Engine.get_frames_per_second()
```

## 22. Common errors and fixes

| Error / symptom | Likely cause | Fix |
|---|---|---|
| `Node not found: "X/Y"` | Wrong or case-mismatched path | Compare with the Scene dock; paths are case-sensitive |
| `Invalid access to property ... on a base object of type 'Nil'` | Variable is `null` (node missing, `@export` unset, freed node) | Assign it; check path; use `is_instance_valid()` |
| `Invalid call. Nonexistent function` | Typo, or the script isn't on that node | Check the script attachment and spelling |
| Signal handler runs twice | Connected both in editor and in code | Keep one |
| `@onready` var is null | Used before `_ready()` or path is wrong | Use inside `_ready()` or later |
| Button unresponsive after pausing | Process mode isn't `Always` | Set it on the UI node |
| Autoload values persist after restart | Autoloads aren't recreated on scene reload | Reset them manually in a `restart()` function |
| Object won't collide | Missing `CollisionShape2D` or shape, or wrong layer/mask | Assign the shape; verify layers and masks |
| `body_entered` never fires | Mask doesn't include the other's layer, or it's an `Area2D` (use `area_entered`) | Fix mask or signal |
| UI is tiny on phone | Default font size on high-res viewport | Raise font sizes; use a Theme |
| UI off-screen or clipped | Anchors not set | Use Layout presets and containers |
| Node appears at wrong place | Local vs global position confusion | Use `global_position` when needed |
| Spawned node doesn't appear | Never added to the tree | Call `add_child(node)` |
| Export fails (Android) | SDK/JDK/keystore path mismatch | Recheck Editor Settings → Export → Android and the official docs |
| Export template error | Template version differs from editor version | Reinstall matching templates |
| Moved a file and references broke | Moved in Explorer, not in Godot | Move inside the FileSystem dock |
